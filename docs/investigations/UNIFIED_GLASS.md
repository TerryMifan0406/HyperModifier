# 作用域内统一玻璃光学参数

入口：首页 / 通知设置 → 全局玻璃材质与模糊 → 统一玻璃材质（独立二级设置页）。默认关闭。
上级页仅显示导航入口与启用摘要；开关、基准选择和 7 项光学参数均在二级页。
复用现有 Activity 详情页导航、返回、主题和滚动容器，不增加运行时 Hook 或渲染路径。
先从已有材质载入基准，再开启统一光学参数并用现有滑块或精确数值弹窗调整。
载入只复制所选材质的 7 项光学参数，不改来源、不自动开启功能；后续来源变更不联动。
可选择通知卡片原生基准、已保存的通知/控制中心卡片、已保存的悬浮通知亮色或暗色参数。

## 筛选与作用方式

统一是绝对覆盖，不是原有卡片功能的增量偏移；只开放下列槽位：

| 槽位 | 参数 | 范围 |
| --- | --- | --- |
| 19 | 边缘强度 | 0–100 |
| 20 | 边缘过渡曲线 | 0.1–8 |
| 21 | 光学厚度 | 0–120 |
| 22 | 反射偏移 | 0–1000 |
| 23 | 反射提亮 | 0–2 |
| 24 | 反射强度 | 0–2 |
| 32 | 折射率 | 1–5 |

反射提亮仅作用于反射项，因此与整体亮度区分后纳入光学统一。
排除所有明度混合、饱和度、压暗、内层着色/alpha、方向光及白色混合、背景、固定/保留项和按压遮罩。
这些参数与界面颜色、对比度、按压状态有关，不能安全地跨材质统一。
模糊半径沿用原有独立全局开关，不纳入这组配方。

基线为 `OS4.0.2.0.XPCCNXM`。使用本地 `aapt2 dump resources reference/MiuiSystemUI.apk` 核对
`notification_glass_params_normal`（`0x7f0300ce`），42 项与现有 `ShadeCardGlassPolicy.defaults()` 完全一致；
APK SHA-256 与 `reference/SYSTEMUI_BASELINE.json` 一致。没有复制旧反汇编或提交参考 APK。
其他基准明确使用模块保存值，不宣称是各设备当前动态材质的采样结果。

## 生命周期和共存

- 复用现有全局 Glass 安装路径，不扩大 LSPosed 包列表。原有只安装材质适配的进程只增加一个原生 setter Hook，
  不因此启动通用 UI Hook、资源 Hook 或桥接服务。沿用抖音进程隔离、模块自身排除和兼容模式边界。
- `View.setMiGlass(float[])` 使用最低优先级，在本模块卡片/超级岛配方调整后覆盖光学项。
  保留上述配方的其他参数；传统 Blur、其他长度配方、非有限配方及全零清除调用不转成玻璃。
- 以弱键保存每个目标最近收到的、尚未统一光学参数的配方。来源可包含本模块单独材质调整。
  原始调用不断更新这份原值；关闭统一功能或模块总开关时恢复最近原值。
- 设置回放绕过本模块卡片/超级岛配方跟踪，避免把统一结果记成原值或重复叠加偏移。
  系统清除/无效配方会移除状态，使已排队的回放失效。
- 玻璃 Hook 兼容模式沿用既有语义：停用后不再争抢材质，完整 Hook 卸载/恢复依赖进程重启。
  不承诺任意第三方模块的相同 setter Hook 顺序；冲突时使用已有兼容模式。
- 新开关和参数进入持久化、运行时 Bundle 和全量备份 schema；旧配置默认关闭，不迁移已有材质开关。

## 性能检查

本次为代码审查与结构检查，没有真机前后性能数据。

- 启动：每个适用进程新增一次原生方法查找、一个 Hook 和一个设置观察器；API 不存在时报告不可用。
- 主线程/动画：每次原生调用做固定 42 项有效性检查和有限数组复制，仅覆盖 7 项；兼容模式及自身回放直接退出。
  不采集调用栈、不解析规则/JSON、不做重复反射查找、磁盘访问或同步 IPC。
- 内存/锁：每目标首次记录时创建状态、两个 42 项数组和一个参数包装数组，后续原生更新复用；弱表值不引用 View/Context。
  弱表锁只用于查找、注册和快照，不在持锁期间调用系统 setter。
- 设置：相关开关/配方 fingerprint 相同则退出；每目标最多一个待处理任务，执行时读取最新配置。
  关闭状态修改参数不会遍历目标；目标未覆盖且无变化时不调用 setter。
- GPU/耗电：复用原生 Glass，无新增截图、模糊层、View 绘制回调、定时器或轮询。
  原生参数改变仍可能改变系统渲染成本，需真机测量，不能据此声称帧率或耗电改善。
