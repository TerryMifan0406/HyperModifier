# 桌面 4×7 与搜索兼容


## 当前结构适配（2026-10-18）

按用户要求移除版本号/长度/FNV 白名单和固定 RVA，删除
`desktop_search_profiles.h`。当前安装使用 `desktop_search_contract.h` 与
`desktop_search_probe.h` 在已加载的 `libapp.so` 可读执行段中定位，不读 APK、
不计算整库哈希。下文版本、地址和哈希为离线分析/历史验证资料，不参与当前运行时判定。

定位保留寄存器、Dart context 字段、栈帧、局部分支、七行资格计算和返回序列的
精确结构，允许 BL 调用地址、对象池 ADD/LDR 操作数和静态表槽变化。两函数
必须保持参数换序、共享 helper、相同设备配置/日志来源、重复几何读取的关联；
布局预览还必须存在唯一的参数换序调用，确认同一判断控制关闭搜索提示。
不接受仅凭一小段通用 prologue 命中，也不放宽已确认的 +15/+19 字段 ABI。

扫描最多 16 个、合计 64 MiB 的映射，不接受重叠、未对齐、地址溢出或越界。
第一遍以廉价参数捕获前缀筛选并校验两函数；第二遍确认布局预览调用，检查
是否有分支跳进会被覆盖的指令中间。命中多组目标或预览见证不唯一时拒绝安装。
定位只在首次启用时在原后台 worker 执行一次；绘制、触摸、动画及资格判断
入口没有新增扫描、分配、锁或 IPC，启停/缓存/双 Hook 就绪与部分失败回滚沿用原实现。

性能结论限于代码审查和结构性变化：去掉原来首次启用时约 28 MiB 的显式文件
读取与逐字节哈希，替换为已加载执行段的两遍有界扫描。关闭时不执行新增扫描。
不能据此声称启动耗时、帧率、功耗已改善，也不承诺字段/寄存器/控制流已改变的
未来编译版本必然兼容。

`desktop-search-probe-test.py` 直接运行生产定位器：两份真实 ELF 自动命中，
无版本和目标地址输入；128 组布局重定位、独立对象池及静态表变化通过；267 组字段/
寄存器/局部分支破坏、callee 角色不一致、目标越界、重复命中、重叠映射和
覆盖块中间入边均拒绝。使用 ASan/UBSan 检查边界，原 4608 组启停/条件码/
Dart 栈/SIMD 汇编入口回归继续通过。主机 sanitizer 扫描耗时仅为调试数据，
不作为 Android 真机性能测量。

校正后的日志字符串，指令以 ELF 原始字节与 NDK llvm-objdump 为准。

7722 的 `LauncherLayoutType` 有两道检查：

- `isLayoutAndSearchCompatibleWithCurrentRows`：`0xa31280`，x2 为布局类型，
  x3 为搜索类型，x5 为当前行数。原逻辑比较搜索所需行数和当前行数，再调用下一道检查。
- `isLayoutAndSearchTypeSupported`：`0xa3142c`，x2 为搜索类型，x3 为布局类型。
  计算原生栅格、搜索预留和剩余空间，最后依据剩余空间是否非负返回 Dart bool。
  `0xa316d8` 是 `CSEL x0,x16,x17,GE` 及完整返回序列。

7751 对应行数检查入口 `0xa318dc`、空间检查函数 `0xa31a88`、返回块
`0xa31d34`；上述寄存器、栈帧和 context 字段 ABI 相同。

布局 0 为四列最大行数，布局 1 为四列最大行数减一，布局 2 为五列；搜索
1/4 与 2/3 使用不同的原生尺寸路径。本次只放开四列最大行数且为七行时的
搜索 2/3，搜索关闭值及 1/4 的现有处理保持原路径。

## 实现边界

新增默认关闭的 `desktop_search_4x7_enabled`，位于「系统界面 → 系统桌面」。
设置持久化、导入导出、全部关闭、作用域提示均接入现有设置模型。
通过现有 SystemUI → 桌面设置载体传递，沿用发送方身份检查与原生设置缓存。

第一处入口仅在布局 0、当前七行、搜索 2/3 时返回 true；其他调用进入原 trampoline。
第二处在原计算完成后检查栈帧保存的实际行数为 7、布局为 0、搜索为 2/3，
再允许原生搜索；否则返回原来的 CSEL 结果。context `+19` 为 tagged 布局，
`+15` 为 tagged 搜索。首版将这两项读反，这是独立于版本拒绝的实现错误。
原先假帧测试也沿用了错误假设，不能证明真实调用 ABI 正确；本次同时修正测试
假帧，并补充独立读取真实 ELF 的 context 写入/调用点验证。第二处复现原本完整的 Dart 返回序列，
避免覆盖紧邻的浮点分配慢路径入口 `0xa316e8`。

7751 的布局预览入口在 `0x14af7dc` 依次执行
`MOV x16,x2; MOV x2,x3; MOV x3,x16; BL 0xa31a88`，明确将布局优先的
调用参数换成搜索优先。返回值取反控制是否进入搜索关闭的确认路径。
因此修正的是提示与关闭搜索共同使用的资格判断，不隐藏对话框文案。

不修改桌面数据库、布局行数、搜索样式或用户搜索开关，不自行创建搜索 UI。
首次安装含本功能的版本后，必须重启系统界面与桌面（或重启手机），使新增
设置载体生效；之后修改此开关再重启桌面，到系统设置开启搜索。系统此前关闭
的搜索不会由模块自动开启。
关闭模块/功能立即停止覆盖后续检查，已有 UI 在重启桌面后由原生规则重建。
关闭前后桌面布局/搜索开关的系统持久化行为仍由系统管理。

初版首次启用时在后台验证完整镜像指纹、可读执行段和两处 16 字节入口；
当前已改为上文所述结构定位。
两处 Hook 均成功后才启用；部分失败只回滚后端明确报告安装成功的地址。
当前结构不匹配或目标被其他模块改写时拒绝安装，不套用历史地址。
